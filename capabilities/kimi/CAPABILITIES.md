# Kimi capabilities (from JS bundle analysis, 2026-09-15; session + UI round-trip live-verified 2026-09-18)

Analyzed 99 JS bundles (~12 MB) from `https://www.kimi.ai` (lang zh-CN, homepage title: "Kimi AI 官网 - K3 上线，专为智能体编程与知识工作打造"). Live-verified host: `www.kimi.ai` (live ChatDriver round-trip 2026-09-18 on `www.kimi.ai/chat/...`); the token/session domain is `.kimi.com` scope.
Transport: **Connect RPC** (connect-es v2, protobuf over HTTP POST, no WebSocket for chat). All RPCs live under `https://notilo.kimi.com`; REST file endpoints under `/apiv2` and `/apiv2-files`. 411 RPC methods across ~45 protobuf services were recovered by decoding the embedded `fileDesc`/`serviceDesc` descriptors.

## 1. Chat core (models, thinking mode, streaming)
- Main RPC: `kimi.gateway.chat.v1.ChatService.Chat` (server-streaming) → `POST https://notilo.kimi.com/apiv2/kimi.gateway.chat.v1.ChatService/Chat`, body = `kimi.gateway.chat.v1.ChatRequest` (Connect/protobuf frames). Alternate entry points (same service): `ContinueChat`, `RegenerateMessage`, `ResumeChat`, `SubscribeMessageStream`, `ChatFromCase`, `CancelChat`, `ReplayChatShareStream`.
- `ChatRequest` fields: `chat_id` (xid/uuidv8), `kimiplus_id`, `scenario` (enum: `SCENARIO_UNSPECIFIED=0, CHAT=1, THINK=2, DEEP_RESEARCH=3, KODER=4, OK_COMPUTER=6, PROBLEM_SOLVE=7, SLIDES=8, KIMI_PLUS=10, SKILLCREATOR=11, AUTOMATION=12, OK_COMPUTER_SWARM=15, BOT=16`), `tools`, `message` (`kimi.chat.v1.ChatMessage`), `options` (`ChatRequestOptions`), `project_id`.
- `ChatRequestOptions`: `thinking` (bool — K3 thinking-mode toggle), `reasoning_effort` (`kimi.common.v1.ReasoningEffort` enum), `context_length` (`kimi.common.v1.ContextLength`), `model` (field 10 — model picker), `system_prompt`, `voice_id`, `lbs`, `slides`, `kimi_claw`, `enable_plugin`, `arena`, `kimi_bot`.
- `kimi.chat.v1.Tool`: `type` (`kimi.common.v1.ToolType`: `TOOL_TYPE_SEARCH=1, IMAGE_GENERATION=2, SEMANTIC_MEMORY=3, AUDIO_GENERATION=4, DEVICE_LBS=5, DEVICE_TOOL=6, PARALLEL_AGENT=7, ASK_USER=8, CRON_JOB=9, GOAL=10, PARALLEL_AGENT_V2=11, BANANA=12, SLIDES_OUTLINE=13`) + `search{force}` and `gen_image{force, ratio:RATIO_1_1/16_9/9_16/4_3/3_4}`.
- Model discovery: `kimi.gateway.config.v1.ConfigService.GetAvailableModels` (`/apiv2/kimi.gateway.config.v1.ConfigService/GetAvailableModels`, proto `GetAvailableModelsRequest_Scene` `UNSPECIFIED|KIMI_WORK=1`) and `ConfigService.GetConfig`. Frontend model/toolbar state keys: `selectSearch`, `selectReasoningEffortV2`, `selectContextLength`, `selectModelEntry`; i18n strings advertise "k3" as "Flagship Model". Scenario-specific surfaces include `Koder` (coding), `Ok Computer`, `Agent Swarm`.
- Streaming: responses come as a stream of `ChatResponse` (protobuf, server-streamed via Connect's HTTP streaming transport) that the client slices into `kimi.chat.v1.Block`/`TextBlock`/`message_ref` segments in `kimi.chatMessages-BjZKZ50i.js`; `ResumeChat` marks `isStreaming=false` after terminal segment and auto-resumes dropped chunks. Errors surface via `kimi.chat.v1.Error`/`Reason` (e.g. `CHATTY_SSE_IDLE_TIMEOUT`, `CHATTY_AGENT_LOOP_INTERRUPTED`).

## 2. Web search / internet mode
- In-chat search is a tool: `kimi.chat.v1.Tool.Search{force}` (type `TOOL_TYPE_SEARCH`); block labels in i18n: `web_search`, `image_search`, `scroll_down`. `GetSearchCitation`/`GetSearchCitationRequest{chat_id, message_id}` returns per-message citation/source list; `GetToolBlock`/`GetToolBlockByShareID` expose the tool block (ungrouped search-result hunks); `VoteMessageRef` allows feedback on refs. `kimi.chat.v1.Refs`/`CodeReference` carry source refs.
- Dedicated search backend (not the chat RPC): `search.v2.SearchService` — `Search`, `SearchImage`, `SearchSaas`, `SerpSaas`, `Highlight`, `Rerank`, `Url2Text`, `GetPdfMeta`; plus `search.v3` protos (`qp.proto` — `SearchIntent` query-parsing, `pdf.proto` — `PDFMeta{md5,url}`, `podcast.proto`, `image.proto`, `video.proto`). Deep research is scenario `DEEP_RESEARCH` with feature gates `DEEP_RESEARCH`, `FEATURE_DEEP_RESEARCH`, `EDUCATION_RESEARCH` → handled as a long-running chatty agent (see `agent.reception.v1.ToolService`).
- URL read: `Url2Text`; chatty agent run-loop can fetch and cite sources (tool-call pages with `running:"Searching…"`, `failed:"Failed to search"`).

## 6. Auth & session facts for automation
- Token storage (exact, from `token-CrFSxcOs.js` localStorage code): keys **`access_token`**, **`refresh_token`**, user id key **`msh_user_id`** (also snapshot key `volcano-token-info` for analytics WebID). Cached in module scope; desktop bridge can override via `invoke("getToken")`.
- API host: **`https://notilo.kimi.com`** (`NOTILO_API_HOST`); auth base `getOAuthBaseUrl()` = `${AUTH_API_HOST}/api` → **`https://auth.kimi.com/api`**; login host `https://login.moonshot.cn`; OAuth host `account.gateway.v1.AuthService`. Region CN/SG dual URLs for fingerprinting SDK.
- Every request carries `Authorization: Bearer <access_token>` (only when token option set, otherwise requestor adds it) plus: `x-msh-version` (web `2.2.0`), `x-msh-platform` (`web` for `/device/register`, `/apiv2/.../GetConfig`, `/apiv2/.../GetAvailableModels`, else `mac/windows` on desktop), `x-msh-device-id` (= VolcanoEngine `webId`), `x-msh-session-id` (= `ssid`), `X-Traffic-Id` (= `userId`), `R-Timezone`, optional `X-Language`, optional **`x-msh-shield-data`** (TrustDecision blackbox), debug header `MSH-Pangolin: true` when `localStorage KIMI__DEBUG_MODE=true`.
- Refresh flow: `refreshAccessToken()` → `AuthService.RefreshToken{refresh_token}` → setToken() writes both keys; on `Code.Unauthenticated` it `cleanToken()` + emits logout; pre-call async device registration `DeviceService.RegisterDevice` (baseURL `/api`). `onlyWebUrls` whitelist shows `/apiv2/kimi.gateway.config.v1.ConfigService/GetConfig` and `GetAvailableModels` are callable as plain "web" platform.
- Anti-bot / fingerprinting signals: **TrustDecision(同盾)** SDK from `td-static.kimi.link` (`_fmOpt={partner:"kimi",channel:"kimi-web",appName:"kimi-web"}`; remote/local FM urls per region) → blackbox string read via `window._fmOpt.getinfo()` and sent in `x-msh-shield-data`. **ByteDance Volcano Engine** analytics (`window.collectEvent`, WebID/ssid/tobid) for AB tests (`project_function_0709`, `membership_landing_page`, `alipay_first`, `plugin_sidebar_entr_0824`…) and user tracking. Dedicated `kimi.gateway.riskcontrol.v1.RiskControlService.ReportEvent` + captcha verification (`kimi.riskcontrol.v1` `CustomPayload`/`captcha_verify`, account errors `REASON_ACCOUNT_CAPTCHA_VERIFY_FAILED`). Quota windows on errors: `QUOTA_EXCEEDED_WINDOW_5H`/`WINDOW_7D`. Near-minified JS with obfuscated chunks; analytics scripts `sg-normal.js`/`cn-normal.js` on `td-static.kimi.link`.
- No bot wall hit when probing with plain `curl` UA `Mozilla/5.0 …Chrome/152.0 …` plus these headers; expect Risk/Captcha gates once abuse signals appear (rate errors strongly typed).

## 7. Suggested ui2api capability list (id, one-line description) — max 12

8. `artifacts` — Generated documents/versioning/share via `ArtifactService` (create/get/list versions/share/copy).
9. `skills` — Install/call Kimi Skills (`SkillService`) with async `SkillJobService` generation jobs.
